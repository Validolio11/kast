# Kast для Android

Android-версія використовує той самий React/Dexie/Supabase код, що й Windows. Дані доступні офлайн; після входу синхронізуються задачі, нотатки, сторінки й фото.

## Встановлення першої збірки

`dist/android/Kast-Android-0.1.4-debug.apk` — підписана стандартним локальним debug-ключем тестова збірка для встановлення напряму на телефон. Скопіюйте APK на телефон і відкрийте його. Android може попросити дозволити встановлення з обраного джерела.

Мінімум: Android 7 (API 24), актуальний Android System WebView/Chrome. Це не публікація в Google Play і не release-підпис для магазину. Для наступних debug-оновлень використовуйте той самий `~/.android/debug.keystore`, щоб зберегти встановлення й дані.

## Збірка

Потрібні Node.js 22+, pnpm 11, JDK 21 та Android SDK із платформою API 36. Вкажіть `JAVA_HOME` та `ANDROID_HOME` (або встановіть Android Studio з його JDK/SDK).

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test:mobile
pnpm build:android
```

Остання команда збирає web assets, виконує `cap sync android`, запускає Gradle `assembleDebug` та `lintDebug`, копіює APK у `dist/android/`. `pnpm android:open` відкриває проєкт в Android Studio.

Для розробки компонування: `pnpm dev:android`. У браузерному перегляді немає Android-плагінів; Google-вхід перевіряється у встановленому APK.

## Google-вхід і синхронізація

Збірка читає тільки клієнтські `RENDERER_VITE_SUPABASE_URL` і `RENDERER_VITE_SUPABASE_ANON_KEY` із локального `.env` (або змінних CI). Не використовуйте service-role/secret key.

У Supabase проєкті Kast → Authentication → URL Configuration → Redirect URLs необхідно додати точну адресу:

```text
com.kast.app://auth/callback
```

Налаштування: <https://supabase.com/dashboard/project/johgerfwsfppdrqwmufk/auth/url-configuration>.

Google Cloud callback залишається Supabase callback; новий OAuth Client Secret для Android не потрібен. Вхід відкриває системний браузер, повертається через Android intent і обмінює одноразовий код PKCE. Верифікатор і сесія зберігаються в приватних Preferences застосунку. Точна адреса callback перевіряється; підтримані скасування, таймаут та відновлення після перезапуску процесу.

28 жовтня 2026 року адресу `com.kast.app://auth/callback` додано до Redirect URLs робочого Supabase проєкту через Dashboard. Перевірка окремого діагностичного OAuth-потоку підтвердила повернення на цю адресу; раніше сервер повертав на `http://127.0.0.1:53682/auth/callback`. Три desktop callback-адреси збережено. Для цієї серверної зміни перевстановлення APK не потрібне: закрийте попередню спробу входу та почніть нову. Повний вхід у Google на фізичному телефоні слід підтвердити окремо.

## Що адаптовано

- Нижня навігація, одноколонковий список → редактор нотатки, safe-area для системних панелей.
- Android Back закриває верхній діалог/меню/перегляд, повертає до списку або до «Сьогодні»; на головному екрані згортає застосунок.
- Видимі touch-ручки медіа, команди переміщення, свайп між фото.
- Налаштування зберігаються між запусками. Резервна копія передається через системне меню Share, імпорт відкриває вибір JSON-файлу.
- Windows-автостарт, глобальна гаряча клавіша та Windows-updater приховані на Android. Фонові OS-нагадування Android у цій збірці не реалізовані.

## Перевірка

`scripts/test-mobile.mjs` містить ізольовані тести callback/PKCE, cancel/timeout races, cold start, settings/storage, backup і desktop IPC. Вони не читають секретів та не звертаються до мережі. Нативна збірка і Android lint мають проходити перед передаванням APK.

Для приймання на фізичному телефоні: створити задачу й нотатку, закрити/відкрити застосунок, перевірити клавіатуру/поворот/Back, додати фото, експортувати й імпортувати копію, виконати Google-вхід і перевірити синхронізацію з Windows. Фізичного Android-пристрою до цього робочого місця наразі не підключено.

## Оновлення через GitHub Releases

Кожен реліз (тег `v*`) збирає, крім інсталятора Windows, підписаний APK `Kast-Android-<версія>.apk` і додає його в той самий реліз (`.github/workflows/release.yml`, job `android`). Встановлений Kast перевіряє останній реліз через кілька секунд після запуску, кожні 6 годин і при поверненні на екран. Якщо версія новіша — у шапці з'являється «Оновлення», а в Налаштуваннях кнопка «Завантажити»: APK завантажується в браузері, Android пропонує встановити його поверх, дані зберігаються.

Підпис — постійний ключ `kast-release.jks` (PKCS12, alias `kast`). Він і пароль не зберігаються в Git: локально лежать у `%USERPROFILE%\.kast-android-signing\`, у CI — у секретах `ANDROID_KEYSTORE_BASE64` і `ANDROID_KEYSTORE_PASSWORD`. **Зробіть резервну копію ключа й пароля**: без них наступні APK не встановляться поверх наявного, доведеться видаляти програму.

Перша підписана версія не встановиться поверх debug-збірки (інший підпис): видаліть debug-версію один раз, після входу в Google синхронізовані дані повернуться. Далі оновлення ставляться поверх.

Локальна підписана збірка: `KAST_KEYSTORE=<шлях до .jks> KAST_KEYSTORE_PASSWORD=<пароль> pnpm build:android:release`. Перевірка в CI без публікації: Actions → «Android APK» → Run workflow.

## Публічна версія

Для Google Play потрібні власний довготривалий upload keystore, Play Console, політика конфіденційності та підписаний release AAB. Ключі не зберігаються в Git. Ця задача не публікує застосунок у магазині.
